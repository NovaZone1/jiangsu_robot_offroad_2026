# 520 左前轮 M1：Nova AI 单轮调参

> 历史测试记录：下文描述当时的测试固件，不是当前启动行为。当前已清理自动试转、默认关闭 Nova AI 试转；
> 上电禁能，原保护和四轮已调参数保留，见 [当前参数与交付说明](motor_pid_20261011.md)。
> `MotorContinuousTest` 已移至 `tests/frame/fixtures`，不参与固件编译；下文旧路径和宏只作历史参考。

> 当前固件已切换到 [M4 持续 100 RPM、Nova 只读监视](motor_m4_continuous_test.md)，本页保留作 M1 历史操作。
> 恢复本页模式需要重新选择端口/模式并编译；当前上电不会自动试转 M1。

> 恢复 M1 AI：`MOTOR_CONTINUOUS_TEST=0`、`NOVA_MOTOR_TUNING=1`、`NOVA_TUNING_PORT=1`。
> 使用 `nova_m1_520_tuned_100rpm_69pct_profile.json`（已固化参数、69%）后重新编译烧录。

这是架空单轮调参固件。M1 接左前轮电机及编码器，M2/M3/M4 每周期保持禁能。
比赛应用不注册、不调度，不需要连接灰度/超声波；上电、连接、查询、加载档案、修改 PID 均不试转。
只有 Nova 明确完成限幅配置并发送非零目标，且停稳互锁通过后，M1 才使能。

## 烧录与连接

1. 在 Nova 停止试验并关闭串口，运行 `tools/ble_bridge/Stop-Bridge.cmd`。
2. 用 DAPLink 在 Keil 下载当前工程（V6），下载后按 RESET。
   编译产物是 `MDK-ARM/jiangsu_robot_offroad_2026/jiangsu_robot_offroad_2026.axf` 和同名 HEX；
   另提供便于识别的 `MDK-ARM/nova_m1_ai_tuned_69pct.hex`。不用 FlyMCU。
3. 架空并固定车体，M1 电机线和编码器线接 M1，电机电源打开，手离开轮子。
4. 运行 `tools/ble_bridge/Start-Bridge.cmd`，看到 READY 后，Nova 连接 **COM12、115200、8N1、无流控**。
   COM11 属于桥接，COM5 属于 DAPLink。不要同时打开两个桥接或让手机占用蓝牙。
   若刚关闭旧桥接后提示没有广播，等约 20 秒再启动；必要时给蓝牙模块断电重上电。
5. 可以先在串口页发送 `LOOP:1`、`PID?`，字符串模式、CRLF，验证返回参数。
   也可以直接进入 AI 调参，握手命令会启动桥接的数据转发。

## Nova 操作

1. 打开 **AI 调参 → 加载方案 / Load**，选择本目录的 `nova_m1_520_tuned_100rpm_69pct_profile.json`。
   不选 Demo，不用通用默认范围。加载后核对：

   | 项目 | 档案值 |
   | --- | --- |
   | 通道 / 模式 | 1 / PI（Kd 锁定为 0） |
   | 固件初值 Kp / Ki / Kd | 0.000957 / 0.009191 / 0 |
   | 目标 | 0 → 100 RPM |
   | 控制周期 / 曲线周期 | 10 ms / 20 ms |
   | 初始稳定条件 | ±3 RPM，保持 1.2 秒，等待上限 8 秒 |
   | 阶跃前 / 后采集 | 1 秒 / 5 秒 |
   | PWM 绝对上限 | 0.69，即 69% |
   | 实际速度范围 | -120～150 RPM（原始及滤波反馈均检查） |
   | 心跳超时 | 1 秒，Nova 每约 200 ms 发心跳 |
   | Kp / Ki 搜索范围 | 0.0002～0.01 / 0.001～0.05 |
   | 最大试验数 | 8，包含最优参数复测 |

2. 第一次选 **每轮确认 / Confirm each trial**，点击 **自动试验 / Start**。
   确认 Nova 的试验提示后，第一轮会实际转动 M1。
   流程为握手、配置、禁能、下发参数、等待零速稳定、100 RPM 采集、停车。
3. 第一轮确认方向正确、转速正值且没有异常后，再使用“确认下一轮”；
   熟悉后可选 **受限自动 / Automatic**，让 Nova 连续比较候选参数。
   不需要手工循环发送目标或心跳，也不要同时用普通 PID 页面改参数。
4. 通过最终复测后，点击 **接受最优 / Accept best** 或 **恢复原参数 / Restore**。
   输出保持停止。参数只保存在 RAM，复位恢复编译时初值；请保存方案或导出试验报告。
   后续根据报告再将实测合适参数固化到工程，不能把模拟测试结果当实物最佳参数。

默认先调 PI。实现支持测量微分的 PID，但首次不参与 Kd 搜索。
这里的调参算法单位是 RPM、秒、归一化占空比；D 对滤波后的反馈求导，
导数再按 `derivative_filter=0.9` 滤波，积分按输出单位限幅并防饱和累积。
M1 单轮架空结果需要在真实负载和整车上复核，不能直接当作其他三轮或巡线参数。

## 停止与保护

- 点 **停止试验 / STOP** 立即请求禁能。异常时可以直接断开电机电源。
- 原 MotorProtection 的方向、无转速、超速、驱动/反馈故障、50 ms 调度间隙及锁定保留。
  DcMotor 原命令超时 250 ms、新鲜度 50 ms、驱动换向互锁和限幅保留。
- 每轮 STOP 立即禁能，后续启动仍要求至少滑行 1 秒、原始速度低于 6 RPM 连续 100 ms；
  3 秒未停稳仍锁定。ACK 表示已禁能，不表示轮子已机械静止。
  下一组 PID 可以在禁能滑行期间准备，目标为 0 时不使能。
- 设备要求 watchdog 为 0.8～2 秒，默认档案 1 秒；超时检查先于输入命令处理。
  单轮从第一条目标命令开始最多 45 秒，心跳或后续目标不延长该时限。
- 设备拒绝绝对值超过 150 RPM 的目标、超过 0.69 的 PWM 限幅，以及放宽到 ±180 RPM 外的
  反馈边界。反向试验必须先停车并完成停稳互锁。当前档案输出上限为 0.69；旧 50% 档案仅作历史记录。
- UART RX 丢帧、TX 错误、ACK/遥测队列失败、心跳超时、限值超限、试验超时均终止并锁定。
  STOP、重新 configure、重复连接均不清除故障；查明原因后关闭 Nova 会话，再按 RESET。
- 通信/调度保护依赖 MCU 任务正常获得执行机会，并不替代独立电源开关或硬件急停。
  BLE 桥接不自动生成心跳，也不重放上次命令。

若提示 `unsafe_limits`：重新加载本档案；若 `waiting_for_standstill`：确认初始目标 0、
稳定保持 1.2 秒、阶跃前采集 1 秒，不要用立即非零启动代替它们。
若方向故障，不要取消保护，先检查 M1 编码器 A/B、输出方向与实际安装。
若 `heartbeat_timeout` 或遥测丢帧，先处理蓝牙/桥接通信再试，不能靠放大超时掩盖问题。

关闭 Nova 串口后需停止并重新启动桥接，READY 后再连接 COM12。
故障定位可看 Keil 中 `NovaLink` 的 `trial_fault_`、`configured_`、`trial_started_`，
以及 `MotorSafety.status_`；调试暂停 CPU 会中断心跳，恢复后应停车而非继续试转。

## 实现和验证

- `Apps/NovaLink`：M1 所有权、试验租期、目标/反馈限值、停稳、故障和遥测。
- `Sys/RtosCpp`、`Apps/MainFrame`：独占调参调度；比赛代码保留，避免两个应用写同一电机。
- `Mods/dc_motor`：可选 D-on-measurement 分支，默认其他模式仍用原 PID。
- `Mods/nova_protocol`：兼容 Nova 省略 type 且 ID 固定的心跳；心跳和 STOP 每次处理。
- `tests/frame/Run-Tests.ps1`：原有模块回归和新的 M1 试验/保护测试。
- `tests/frame/Check-NovaM1Automatic.py --nova-root <Nova源码目录>`：
  原版 AutomaticTuner 对接生产 C++ 控制器与模拟电机，验证多轮试验到最终接受；无需蓝牙，不转实物。
